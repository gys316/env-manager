# envsync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 레포의 `.env`/YAML 비밀값 파일을 Bitwarden(`bw` CLI)으로 push/pull 하는 Node CLI `envsync`를 만든다. 옵션으로 SOPS 암호화 모드(암호화 파일은 git, age 키만 Bitwarden)를 지원한다.

**Architecture:** 외부 프로그램(`git`, `bw`, `sops`)은 모두 셸 없이 호출하는 `Runner` 함수 하나를 거친다. 그 위에 `Vault`(Bitwarden)와 `Sops` 어댑터를 두고, 원격 저장 방식은 `Backend` 인터페이스(vault/sops 구현 2개)로 추상화한다. 명령(init/push/pull/status/add/remove)은 `Backend`, 설정, 동기화 상태, `Io`(출력·확인 프롬프트)만 알고, 어댑터는 테스트에서 가짜로 바꿔 끼운다.

**Tech Stack:** Node.js ≥ 20 (개발 환경 v22), TypeScript 5 (ESM, `"type": "module"`), `commander` 14, `yaml` 2, `age-encryption` 0.2 (typage), 테스트는 `vitest` 3. 외부 프로그램: `bw` (Bitwarden CLI), `sops` ≥ 3.9, `git`.

**Spec:** `docs/superpowers/specs/2026-10-22-envsync-design.md`

## Global Constraints

- 명령 이름 `envsync`, 레포별 설정 파일 이름 `.envsync.config`(JSON, 레포 루트, 커밋 대상, 비밀값 없음).
- 설정 형식: `{ "version": 1, "repo": "owner/repo", "mode": "vault" | "sops", "files": [...], "sops"?: { "recipient": "age1..." }, "formats"?: { "<path>": "binary" } }`. `files`는 레포 루트 기준 상대경로, 항상 `/` 구분자.
- Bitwarden: 폴더 `envsync`, 항목 타입 Secure Note(`type: 2`, `secureNote: { type: 0 }`). 항목 이름 `envsync:<owner>/<repo>:<파일경로>`, sops 키 항목은 `envsync:<owner>/<repo>:age-key`. 이름은 완전 일치로 찾고, 2개 이상이면 오류로 멈춘다.
- sops 암호화 파일은 `<파일>.enc`(원본 옆). 개인키는 환경변수 `SOPS_AGE_KEY`로만 전달한다.
- 동기화 상태는 `<git-dir>/envsync/state.json`에 해시(SHA-256 hex)와 원격 버전만 저장하고 값은 저장하지 않는다.
- 백업 파일은 `<파일>.envsync-backup`. `init`은 `.gitignore`에 `*.envsync-backup` 패턴을 추가한다.
- **비밀값(파일 내용, 키, 마스터 비밀번호, 세션 토큰)은 stdout/stderr 출력, 로그, 임시파일, 커맨드라인 인자에 절대 넣지 않는다.** 자식 프로세스에는 stdin이나 환경변수로만 넘긴다. 모든 출력(텍스트, JSON)은 키 이름과 경로까지만 담는다.
- 외부 명령은 `child_process.spawn`으로 `shell: false`로 호출한다.
- 사용자에게 보이는 메시지는 한국어로 쓴다.
- vault 모드에서 파일의 UTF-8 바이트 길이가 7000을 넘으면 `NOTE_TOO_LARGE` 오류로 멈추고 sops 모드를 권한다.
- 파일 내용은 항상 바이트 그대로 다룬다(CRLF, BOM, 한글 포함). 비교도 바이트 단위로 한다.
- 종료 코드와 오류 코드 (Task 1에서 정의하고 SKILL.md에 그대로 옮긴다):

| exit | code | 의미 |
|---|---|---|
| 0 | — | 성공 |
| 1 | `UNEXPECTED` | 예상하지 못한 오류 |
| 2 | `NOT_INITIALIZED` / `USAGE` / `NOT_GIT_REPO` / `ALREADY_INITIALIZED` / `UNSUPPORTED_FILE` | 설정 없음, 사용법 오류 |
| 3 | `NOT_LOGGED_IN` | `bw login` 필요 |
| 4 | `VAULT_LOCKED` | 잠겨 있고 비대화형이라 잠금을 풀 수 없음 |
| 5 | `CONFLICT` | 원격이 마지막 동기화 이후 바뀌었거나, 기준 없이 내용이 다름 |
| 6 | `PULL_SKIPPED` | 로컬 내용이 달라 pull에서 건너뛴 파일이 있음 |
| 7 | `MISSING_DEPENDENCY` | `bw`/`sops`가 없거나 sops 버전이 3.9 미만 |
| 8 | `CONFIRMATION_REQUIRED` | 비대화형인데 `--yes` 없이 확인이 필요한 작업 |
| 9 | `NOTE_TOO_LARGE` / `DUPLICATE_ITEM` / `BW_ERROR` / `SOPS_ERROR` | 저장소 쪽 오류 |

## Review Focus

- **npm으로 설치한 `bw`(Windows의 `bw.cmd`)**: Node 20+는 `.cmd`를 `shell: false`로 spawn하지 못한다(EINVAL). 사용자는 그래도 동작하길 기대한다 → Task 1의 `resolveExecutable` 테스트로 고정.
- **CRLF 줄바꿈, BOM, 한글 값이 든 파일**: pull 결과가 push한 원본과 바이트 단위로 같아야 한다 → Task 8 테스트로 고정.
- **레포 하위 폴더에서 실행**: `backend/`에서 `envsync pull`을 해도 레포 루트 기준으로 동작해야 한다 → Task 2(`findRepoRoot`)와 Task 9(`createContext`) 테스트로 고정.
- **pull 대상의 상위 폴더가 없음**(예: `backend/`가 아직 없는데 `backend/.env`를 받음) → 폴더를 만들고 쓴다. Task 8 테스트로 고정.
- **origin remote가 없는 레포, GitHub가 아닌 remote**(`ssh://git@host:2222/o/r.git`, GitLab 하위 그룹) → `parseRemote`가 `owner/repo` 또는 `group/sub/repo`를 돌려주고, 없으면 `--repo` 옵션을 요구한다. Task 2와 Task 7 테스트로 고정.

### Task 7: 원격 저장소 Backend (vault / sops)

**Files:**

**Interfaces:**
- Consumes: `Vault`, `Note`, `Sops`, `SopsFormat`, `Config`, `fileFormat`, `sha256`, `EnvsyncError`
- Produces:

  - `interface Backend { read(path: string): Promise<Remote | null>; version(path: string): Promise<string | null>; write(path: string, content: Buffer): Promise<{ version: string; warning?: string }> }`
  - `noteName(repo: string, path: string): string` → `envsync:<repo>:<path>`; `keyNoteName(repo)` → `envsync:<repo>:age-key`
  - `class VaultBackend implements Backend { constructor(vault: Vault, config: Config) }`
  - `class SopsBackend implements Backend { constructor(root: string, vault: Vault, sops: Sops, config: Config, onConfigChange: (c: Config) => Promise<void>) }`

**VaultBackend:** `read` → `findNote(noteName)`로 `{ content: Buffer.from(notes, 'utf8'), version: revisionDate }`. `write` → UTF-8 바이트 > 7000이면 `NOTE_TOO_LARGE`(hint: `envsync init --encrypt`로 sops 모드 사용). `upsertNote` 후 `revisionDate`를 version으로. 내용은 `content.toString('utf8')`로 넘긴다. Task 5의 FakeVault와 실제 bw 모두에서 CRLF가 보존되는지 Task 12에서 직접 확인한다.

**SopsBackend:** `<root>/<path>.enc`를 다룬다. 개인키는 처음 필요할 때 `findNote(keyNoteName)`에서 읽어 인스턴스 메모리에만 둔다(없으면 `NOT_INITIALIZED`, hint: 키가 Bitwarden에 없음). 형식은 `config.formats?.[path] ?? fileFormat(path)`.
- `version(path)`: `.enc` 파일 바이트의 sha256, 없으면 null.
- `read(path)`: `.enc`가 없으면 null, 있으면 `decryptFile` 결과와 version.
- `write(path, content)`: (1) 기존 `.enc`가 있으면 복호화해서 `content`와 같으면 아무것도 쓰지 않고 기존 version을 돌려준다. (2) 형식 `f`로 `encryptFile(<root>/<path>, f, recipient)` → `.enc`에 쓴다 → 바로 `decryptFile`해서 `content`와 바이트 비교. (3) 다르고 `f !== 'binary'`이면 `binary`로 다시 암호화해 덮어쓰고, `config.formats[path] = 'binary'`로 바꿔 `onConfigChange`를 호출하고, `warning: '<path>: SOPS <f> 형식에서 내용이 보존되지 않아 binary 형식으로 암호화했습니다 (git diff에 키 이름이 보이지 않음)'`. `encryptFile`은 작업 트리의 평문 파일을 읽으므로, `write`에 넘어온 `content`가 디스크 파일과 같아야 한다는 전제를 주석으로 남긴다(push는 항상 디스크에서 읽은 내용을 넘긴다).

  - `type FileStatus = 'synced' | 'local-changed' | 'remote-changed' | 'conflict' | 'local-only' | 'remote-only' | 'missing' | 'differs' | 'pushed' | 'pulled' | 'unchanged' | 'skipped' | 'local-missing' | 'remote-missing'`
  - `push(ctx: Context, opts: { yes: boolean; force: boolean }): Promise<FileResult[]>`
  - `pull(ctx: Context, opts: { force: boolean }): Promise<FileResult[]>`
  - `status(ctx: Context): Promise<FileResult[]>`
- 명령들은 Bitwarden 잠금 해제와 `bw sync`를 하지 않는다(그건 Task 9의 `createContext`가 한다). 결과 배열은 `config.files` 순서.

**push 규칙 (파일마다):**
1. 로컬 파일이 없으면 `local-missing`.
2. `remote = backend.read(path)`, `rec = state.get(path)`.
3. `remote`가 있고 `rec`가 있고 `remote.version !== rec.remoteVersion` → force가 아니면 `conflict`.
4. `remote`가 있고 `rec`가 없고 내용이 다르면 → force가 아니면 `conflict`.
5. `remote` 내용 == 로컬 → `unchanged`, `state.set(path, { hash, remoteVersion: remote.version })`.
6. 나머지는 쓰기 후보로, `diffKeys(remote?.content ?? null, local, format)`을 붙인다. 형식은 `fileFormat(path)`. binary로 기록된 sops 파일은 diff를 계산하지 않고 `opaque: true`.

- 하나라도 `conflict`가 있으면 아무것도 쓰지 않고 `CONFLICT`를 던진다(hint: `envsync pull` 후 다시 push, 또는 `--force`). 결과는 오류에 실어 CLI가 출력하게 한다(`EnvsyncError`에 `details?: unknown` 필드 추가).
- 쓰기 후보가 있으면 요약을 `io.info`로 출력한다(파일별 `+추가 ~변경 -삭제` 키 이름). `yes`가 아니고 `io.interactive`이면 `io.confirm('위 변경을 반영할까요?')`, 비대화형이면 `CONFIRMATION_REQUIRED`. 거절하면 아무것도 쓰지 않고 후보를 `skipped`로 돌려준다.
- 쓰기: `backend.write` → `pushed`(+warning), `state.set(path, { hash: sha256(local), remoteVersion })`. 끝나면 `state.save()`. sops 모드면 `.enc 파일을 git에 커밋하세요` 안내.

**pull 규칙 (파일마다):**
- `remote`가 없으면 `remote-missing`. 모든 파일이 `remote-missing`이면 `io.warn('Bitwarden에 이 레포의 저장된 파일이 없습니다')`.
- 로컬이 없으면 상위 폴더를 `mkdir -p`하고 쓴다 → `pulled`.
- 로컬 == 원격이면 `unchanged`.
- 다르면: force가 아니면 `skipped` + diff(원격 → 로컬 방향 기준 키 이름). force면 `<path>.envsync-backup`에 기존 내용을 쓰고 `ensureIgnored(runner, root, ['*.envsync-backup'])` 후 덮어쓴다 → `pulled`.
- 쓰거나 `unchanged`인 파일은 `state.set`. 끝나면 `state.save()`. `skipped`가 하나라도 있으면 결과를 실어 `PULL_SKIPPED`를 던진다(hint: `--force`로 덮어쓰기, 기존 파일은 백업됨).

**status 규칙:** 읽기 전용(상태 파일도 쓰지 않음).
- 로컬·원격 둘 다 없으면 `missing`, 로컬만 있으면 `local-only`, 원격만 있으면 `remote-only`.
- 둘 다 있고 `rec`가 있으면: `backend.version`과 로컬 해시로 `synced` / `local-changed` / `remote-changed` / `conflict`(원격을 복호화하지 않음).
- 둘 다 있고 `rec`가 없으면 `backend.read`로 내용 비교 → `synced` / `differs`.
